# 概率第一课：为什么 20 次零失败不等于可靠

一个客服 Agent 在演示中连续回答正确 20 次。负责人问：“是不是可以认为它的错误率为零？”这句话听起来有道理，却把**已观察到的结果**和**未来任务中的真实失败概率**混为一谈。

本课用虚构数字解释概率、二项分布与置信区间，并运行一个标准库示例。它不是用几行公式给系统做安全认证；真实评估还要考虑任务覆盖、评分错误、环境变化和不同用户群体。

## 1. 一次结果与长期概率是两回事

假设某个固定任务的每次尝试都只有“失败”或“未失败”两种结果，且每次失败概率都是 $p=0.05$。那么一次未失败的概率为 $1-p=0.95$。**如果**各次尝试相互独立、失败概率保持不变，20 次都未失败的概率为：

$$
P(\text{20 次零失败})=(1-0.05)^{20}\approx0.358
$$

也就是说，在这个假设模型里，即便每次有 5% 的失败概率，连续 20 次没有看到失败仍然并不罕见。这里的 5% 是**事先设定的教学假设**，不是从 20 次结果里算出的真实值。反过来，观察到零失败也不能直接推出未来失败率等于 5% 或 0%。

独立性很关键：如果 20 次都使用同一份缓存、同一份错误配置或彼此有交接状态，一次环境问题可能影响多次结果；如果 20 次都是同一个简单问题，它们也不能代表复杂任务。Anthropic 的 [Agent 评估实践](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)强调隔离试验与共享环境造成的相关性。

## 2. 二项分布：描述一组假设下的计数

若每次尝试独立、失败概率固定为 $p$，做 $n$ 次尝试，失败次数 $X$ 服从二项分布：

$$
P(X=k)=\binom{n}{k}p^k(1-p)^{n-k}
$$

组合数 $\binom{n}{k}$ 表示从 $n$ 次中选择哪 $k$ 次失败；后面两项是一个具体失败/未失败排列的概率。这个公式可以回答“**已假设**每次失败概率是 5%，20 次里恰好失败 2 次有多大概率？”它不能自动回答“**观察到** 2 次失败，真实概率一定是多少？”

真实 Agent 的任务难度往往不同，同一任务重复运行的结果也可能相关；把所有运行混成同一个二项模型之前，应先说明任务如何抽样、环境是否隔离、什么算失败。条件不满足时，简单公式产生的数字可能误导决策。

## 3. 用区间表达估计的不确定性

假设一组具有代表性的独立同分布试验中，100 次失败 5 次，观察到的失败比例为 $\hat p=5/100=5\%$。用 Wilson 方法计算的双侧 95% 置信区间约为 **2.2% 到 11.2%**；范围比单点“5%”更能提醒我们样本有限。

置信区间的频率学派解释是：在相同抽样机制和模型条件下反复构造区间，这种方法在长期中约有 95% 的区间覆盖固定但未知的参数。它不是“这次固定参数有 95% 概率落在这个已算出的区间里”；也不覆盖选择样本偏差、评分器错误或未来业务分布变化等所有不确定性。

Wilson 区间使用近似方法，适合本课建立直觉，但也有覆盖率限制；在稀有事故或高风险控制中，应结合更适合的统计方法、专家判断与定向对抗测试，而不是将一个小样本区间当作上线批准。

## 4. 运行示例

在仓库根目录运行 Python 3.10+：

```bash
cd examples/probability-evals
python3 metrics.py
python3 -m unittest -v
```

预期分别看到约 `0.358` 和 `[0.022, 0.112]`；4 条测试检查二项概率归一、零失败时的区间上界、观测比例以及非法输入。[完整源码](https://github.com/xiaoqianbaobao/ai-guide/tree/main/examples/probability-evals)没有第三方依赖。

下面是计算“20 次零失败”的核心逻辑：

```python
from math import comb

def binomial_probability(n, k, p):
    return comb(n, k) * p ** k * (1 - p) ** (n - k)

print(round(binomial_probability(20, 0, 0.05), 3))  # 0.358
```

示例代码额外校验取值；大型 $n$ 或极端概率可能涉及数值稳定性，严肃分析应使用经过验证的统计软件，不应直接把教学函数用于高风险报告。

## 5. 如何把数学带回企业评估

假设你要评估知识助手：

1. **先定义单位：** 是同一道题的重复尝试，还是从真实工作中抽取的不同任务？成功是否同时要求答案正确、引用有效且权限合规？
2. **分层采样：** 按任务类型、难度、租户与异常场景分别报告，不让大量简单问题掩盖困难场景。分层后的合并指标需要写明权重来源。
3. **重置与记录：** 每次运行的模型版本、提示词、工具权限、数据与缓存必须可追溯；共享环境可能让结果相关。
4. **报告计数和分母：** 写“5/100 次失败”与区间，而不是只写“准确率 95%”；保留失败案例及评分理由。
5. **单列严重风险：** 越权和数据泄露不能被平均成功率抵消。没有观察到泄露，也不等于已经证明泄露概率为零。

这个框架和 [知识助手回归评估](../agent/cases/knowledge-assistant-evaluation)互补：后者是确定性的教学基线；加入有随机性的模型后，才需要设计多次运行、抽样和统计报告。

## 6. 练习

1. 如果假设每次失败概率为 10%，且 20 次独立尝试，计算零失败概率；与 5% 的情景比较。
2. 分别计算 `wilson_interval(0, 20)` 和 `wilson_interval(0, 200)`，观察上界如何变化；说明“范围更窄”并不能修复偏样本。
3. 设计两组测试：一组对同一道题重复运行，另一组覆盖不同客户任务。说明它们各自能回答什么问题、不能回答什么问题。
