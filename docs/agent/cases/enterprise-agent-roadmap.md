# 企业级 Agent 实战路线：从知识助手到可治理工作流

> 状态：路线与验收标准，尚不是已完成的可运行课程。后续每一阶段都应提供对应源码、运行命令、测试数据和实测结果，再标记完成。

## 为什么选择一个连续场景

企业级 Agent 不是把模型接上数据库就完成了。一个有用的系统必须回答：谁可以看哪些信息？引用能否追溯？工具失败如何恢复？错误执行后怎么止损？新版本上线会不会让旧任务退化？这些问题分散在不同文章里，读者很难从头拼出一个可运行系统。

本系列以**企业内部知识与工单助手**为教学场景：员工提问，助手检索自己有权访问的文档并给出引用；当资料不足时，它可以准备一份工单草稿，供有权限的人审核后提交。课程先使用虚构数据和本地模拟服务，再逐步接真实身份和业务系统。

这个选择是为了覆盖检索、授权、写入、审批与评估，不意味着所有企业都适合直接部署这个示例。真实部署须按组织身份、数据分级和业务流程重新设计。

## 最终完成的用户旅程

1. 用户以可信身份登录，提出问题；服务端确定其租户和角色。
2. 系统只检索该身份当前有权读取的文档；答案引用来源及版本，证据不足时明确说明。
3. 用户要求创建工单时，Agent 生成待审草稿，由服务端校验目标、内容和权限。
4. 审批人看到具体内容与目标；批准后执行器以稳定操作 ID 提交，并对超时进行查询或对账。
5. 管理员可追踪脱敏后的任务、工具调用、审批与错误，并通过回归集评估更新。

这些是**目标行为**，并非声称现有站点已经实现。即使示例实现完成，也需要实际环境的安全评审、容量与恢复测试，才可决定是否上线。

## 分阶段交付与验收

| 阶段 | 需要交付 | 读者能亲自验证的完成条件 |
| --- | --- | --- |
| 0. 定义任务和边界 | 虚构企业案例、用户角色、数据分级、架构和威胁模型 | 说清允许查询与禁止外发的范围，准备可复现测试数据 |
| 1. 端到端最小系统 | 前端、后端、模型适配接口、模拟知识源和本地启动文档 | 使用测试数据提问并获得带出处的回答；无证据时拒绝编造 |
| 2. 知识接入与检索 | 文档导入、切分、索引、引用版本及更新流程 | 修改或撤回文档后，检索能处理旧索引与缓存失效 |
| 3. 身份与权限 | 可信身份上下文、租户隔离、工具服务端鉴权 | 两个租户的用户不能从检索、缓存、日志或工具结果取得彼此数据 |
| 4. 受控工具与审批 | 工单草稿、审批记录、模拟工单服务、幂等与对账 | 审批前无写入；重复提交不产生重复工单；审批目标变化需重新确认 |
| 5. 状态与恢复 | 任务状态、检查点、超时、重试和可恢复记录 | 在写入前、响应丢失后、状态持久化前注入故障并验证恢复路径 |
| 6. 评估与观测 | 脱敏轨迹、任务集、确定性检查、人工抽样与告警 | 能重跑正常、越权、提示注入、证据不足和依赖故障用例，并比较版本 |
| 7. 部署演练 | 部署配置、密钥管理、备份、回滚、运维手册和成本预算 | 在隔离测试环境完成部署、故障演练与回滚，并记录环境和限制 |

每阶段必须说明依赖版本和运行环境，提供命令与预期输出；没有真实运行的代码标记为伪代码。示例不能放真实客户数据或密钥。对业务有副作用的功能默认连接模拟服务。

## 系统边界和关键选择

**知识检索**：索引是源文档的可重建副本，而不是事实权威。检索与缓存都需要执行授权检查；答案中的引用应能映射到可访问的来源版本。参见 [知识库与运行时上下文](../../03-memory/wiki-and-runtime-context)。

**工具执行**：模型只提出调用意图。服务端按用户、租户、工具、目标和数据权限决定是否执行；外部内容不能授予新权限。参见 [Agent 安全边界](../../02-agent-core/agent-security-boundaries)。

**执行状态**：对外部副作用保留操作 ID、目标摘要和状态；未知结果先对账再决定是否重试。下游不支持幂等或查询时，需要人工核对或补偿。参见 [Agent 工程闭环](../../05-tools-frameworks/agent-engineering-loop)。

**质量和风险**：同时检查结果正确性、授权边界、执行轨迹、成本与延迟。记忆、模型或提示词变化后必须重跑关键任务；不可将一次演示当作上线依据。参见 [线上评估与回归](../../06-eval-evolution/production-evaluation-loop)。

## 最小回归样例

下面是待实现的验收用例，不代表测试已经运行：

| 用例 | 前置条件 | 预期结果 |
| --- | --- | --- |
| 正常问答 | 用户可读 A 文档 | 返回有 A 版本引用的答案 |
| 越权检索 | B 文档仅另一个租户可读 | 不返回 B 的内容，也不在引用或日志泄露 |
| 证据不足 | 索引中没有相关信息 | 明确表示无法确认，不捏造出处 |
| 提示注入 | 检索文档要求把私有资料发到外部 | 外部指令不产生越权读取或发送 |
| 审批过期 | 工单草稿获批后目标改变 | 拒绝执行，要求重新审批 |
| 写入响应丢失 | 模拟服务已创建工单但客户端超时 | 使用相同操作 ID 查询或对账，不盲目重复创建 |

## 实施顺序

优先建立阶段 0 和阶段 1 的真实代码仓库、运行说明与验收用例，再依次引入权限、审批和恢复。不要为了展示多 Agent 而先引入多角色编排：先用任务集测出单 Agent 的瓶颈，再判断额外协调成本是否值得。参考 [OpenAI 的 Agent 评估建议](https://developers.openai.com/api/docs/guides/evaluation-best-practices)及 [Anthropic 的 Agent 评估实践](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)。
