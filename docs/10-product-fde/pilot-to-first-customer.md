# 从试点到第一个客户：用证据验证价值

演示中 Agent 回答了一个问题，不等于它为企业创造了价值。客户需要知道：它能否在自己的工作流程里稳定工作、节约多少时间、引入什么风险、谁来维护，以及投入是否值得。

本文沿用虚构的企业知识与工单助手案例。数字均为演算示例，不代表实际客户、项目结果或价格建议。试点的目标是产生双方都认可的证据，而不是证明最初想法一定正确。

## 1. 一页纸约定试点

在接触真实资料之前，与客户约定以下内容，必要时让信息安全、业务和采购参与：

| 项目 | 示例 |
| --- | --- |
| 业务目标 | 缩短处理常见退款规则问题的时间，同时保持回答可追溯 |
| 范围 | 一个小组、一类问题、经批准的资料；只读查询，不自动提交工单 |
| 参与者 | 一线使用者、业务负责人、资料维护人、技术与安全联系人 |
| 对照 | 同一类任务记录原流程与试点流程；尽量控制任务难度与人员差异 |
| 指标 | 正确且有有效引用的任务比例、人工复核时间、不可回答时的处理、用户继续使用情况 |
| 风险边界 | 权限隔离、资料更新、日志脱敏、错误升级与停止试点方式 |
| 交付 | 试点报告、问题清单、下一步选择；无权访问的数据不得用于测试 |

把“回答快”与“完成得好”分开计量。如果答案生成时间缩短，但用户要花更多时间核实引用，整体效率未必提高。用户满意度可以帮助解释原因，但不能代替任务结果。

## 2. 设计可信的对照

先记录现有工作：任务从接收至完成的时间，实际执行者的操作、等待、返工与风险。再用相同口径观察试点。对于小样本，不要把一次试点的差异说成精确预测，也不要只挑表现最好的任务。

例：使用经授权的 20 个代表性任务，记录人工处理时长和试点后的总耗时，其中包括生成、检查与修正。再单独记录引用错误、越权、无法回答和人工升级。任务难度不同会影响对比；记录样本与分配方式，必要时由业务人员盲审结果。20 只是示范数量，是否足够取决于风险与任务多样性。

高风险指标需要单独设置门槛：即使平均耗时减少，也不能用它抵消一次严重越权。权限隔离、审批、恢复与回归用例参见 [企业级 Agent 实战路线](../agent/cases/enterprise-agent-roadmap) 和 [Agent 安全边界](../02-agent-core/agent-security-boundaries)。

## 3. 用范围而不是单点承诺测算价值

假设每月有 1,000 次相关任务，原流程平均 8 分钟；试点后平均操作和复核合计 5 分钟。若每小时人工成本按 60 元估算：

```text
理论节约 = 1,000 × (8 - 5) ÷ 60 × 60 = 3,000 元/月
净收益估计 = 可实现的节约 - 模型与基础设施成本 - 运维与复核增量
```

这里 3,000 元只是**理论时间价值**。时间节约未必转换为现金；真实采用率、重复任务、固定成本、风险和上线成本都可能改变结果。建议至少给出保守、基准和乐观三种情景，并写出假设来源。客户更关心处理能力或服务质量时，应同时展示这些结果，不必把一切硬折算成节省人力。

## 4. 从试点承诺走向合作提案

试点结束时，不要只展示正确答案，应该与客户一起回答：哪些任务适用？什么情况下必须升级给人？指标是否达标？谁负责数据维护？继续推广前还需要哪些安全、采购和技术审查？

一个可讨论的提案可以包括：

1. **现状与证据：** 哪个角色遇到什么问题，试点观察了哪些任务。
2. **目标与范围：** 本次交付什么、不包含什么，成功标准由谁确认。
3. **实施与责任：** 客户和供应商分别提供哪些数据、人员和系统权限。
4. **费用与假设：** 一次性实施、持续使用、运维支持分别如何计价；哪些量变会调整报价。
5. **风险与退出：** 数据处理、故障升级、终止后数据处置，以及未达标怎么办。
6. **下一步：** 明确决策者、采购流程、审查材料与下次沟通时间。

“愿意参加下一次会议”是弱承诺；安排业务负责人、提供已授权样本、确认预算流程或签署合同，是不同强度的承诺。不要把口头兴趣记作收入，也不要把案例中的假设写成自己的业绩。

## 5. 把试点变成下一轮学习

复盘时把任务分为成功、失败和不适用；记录证据来源、责任人与修复优先级。功能不足可以修，资料没有权威来源可能需要客户先治理知识；若试点无法达到安全边界，停止也是合理结果。经授权后，才能把客户反馈整理成公开案例。

## 练习：写一页试点方案

选一个你能实际接触的工作场景，填写本文第一张表；请一名潜在使用者和一名负责人分别指出最担心的部分。设计 5 个普通任务和 2 个异常任务，并明确退出条件。没有真实客户时，可先用虚构数据演练，但报告必须标记为模拟。
